# 项目定位与实施原则

[返回学习入口](./index.md) · [下一篇：主线实施计划](./02-mainline.md)

## 学习目标

覆盖 `sgl-model-gateway` 的主要设计和实现思路，每类能力做一个最小实现。完整复刻会把时间消耗在协议和部署细节上。

| 层次 | 例子 | 学习目标 |
|---|---|---|
| Rust 语言 | 所有权、借用、枚举、trait、泛型 | 能自己写、能解释编译错误 |
| 库与运行机制 | Tokio、Axum、Serde | 理解异步任务、HTTP、序列化 |
| 网关业务 | 负载均衡、重试、熔断、PD 路由 | 知道解决什么问题、如何验证 |

Rust 不必为了覆盖语法而强行引入 `unsafe`、复杂宏或手写 `Future`。

## 实施约定

| 项目 | 约定 |
|---|---|
| 项目名称 | `my-smg` |
| 工程位置 | 独立目录、独立 Cargo 项目，避免继承原项目的大量依赖 |
| 学习方式 | 先独立实现最小功能，再对照原仓库 |
| 运行环境 | 本机运行，使用假模型节点，无需 GPU 和真实模型 |
| 功能范围 | 每类能力做一个最小实现，完整协议兼容放到扩展阶段 |
| 代码规模 | 每个任务以一次能理解、能验证的小改动为单位 |
| 引入抽象 | 先具体类型，出现实际需求后再引入 trait、泛型、共享状态 |
| 验收标准 | 功能通过测试，并且能解释关键代码 |
| 进度依据 | 按验收推进；时间估计不作为硬期限 |

## 最终运行形态

```text
                  curl / 自动化测试
                          |
                          v
                +-------------------+
                |      my-smg       |
                |                   |
                | 配置 / 请求校验   |
                | 限流 / 模型路由   |
                | 节点选择 / 转发   |
                | 超时 / 重试       |
                | 熔断 / 流式响应   |
                +---------+---------+
                          |
                 +--------+--------+
                 v                 v
             假节点 A          假节点 B
             正常响应          延迟 / 报错
             SSE 分段          中途断开

后台任务：健康检查、节点变更、优雅停机
观测能力：请求日志、节点负载、错误与延迟指标
```

## 目录演进

开始只建必要文件：

```text
my-smg/
├── Cargo.toml
├── src/
│   ├── main.rs
│   ├── lib.rs
│   ├── worker.rs
│   └── policy.rs
└── learning/
    ├── index.md
    ├── 01-project.md
    ├── ...
    └── lessons/           # 每课记录，按需创建
```

随着功能增加，再演进为：

```text
my-smg/
├── src/
│   ├── bin/
│   │   ├── my-smg.rs
│   │   └── fake-worker.rs
│   ├── lib.rs
│   ├── config.rs
│   ├── error.rs
│   ├── worker/
│   ├── policy/
│   ├── gateway/
│   ├── reliability/
│   └── telemetry.rs
├── tests/
│   ├── routing.rs
│   ├── reliability.rs
│   └── streaming.rs
├── configs/
└── learning/
    ├── index.md
    ├── ...
    └── lessons/
```

以上是目标结构，随阶段创建；迁移到 `src/bin/my-smg.rs` 时同步调整原二进制入口。

依赖逐步增加：**标准库 → 配置解析 → HTTP/异步 → 观测与扩展**。具体版本在实施对应阶段时确定。
