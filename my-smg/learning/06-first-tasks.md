## 本阶段实现边界

| 项目 | 约定 |
|---|---|
| 节点 | 先保存 ID 和健康状态，不连接真实服务 |
| 节点集合 | `Vec<Worker>`；选择函数接收切片 |
| 轮询状态 | 普通计数器，通过 `&mut self` 更新 |
| 返回值 | `Option<usize>`，索引指向原节点列表 |
| 没有可用节点 | 返回 `None`，不 panic |
| 依赖 | 仅标准库 |
| 并发与网络 | 在主线后续阶段增加 |

## 最小行为样例

以下每行从新建轮询器开始；健康节点列表按输入顺序排列。

| 节点状态 | 连续选择结果 |
|---|---|
| 空列表 | `None` |
| A 健康 | `A, A, A` |
| A、B、C 都健康 | `A, B, C, A` |
| A、C 健康，B 不健康 | `A, C, A, C` |
| A、B、C 都不健康 | `None` |

动态变化测试重点验证：B 被标记为不健康后不再被选择；恢复后，在健康集合保持稳定时能够再次轮到 B。暂不要求健康集合变化前后保持固定的全局轮询顺序。

## 完成后必须能解释

1. 节点列表由谁拥有？选择函数为什么借用它？
2. 为什么修改节点状态和轮询计数需要可变访问？
3. 为什么返回 `Option<usize>`？`None` 表达什么？
4. 健康列表里的位置与原节点列表的索引有什么区别？
5. 哪些地方需要复制或克隆，哪些地方只需要借用？
