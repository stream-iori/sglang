## 每课固定流程

```text
给出行为目标与样例
        |
        v
你写最小实现
        |
        v
编译错误 -> 定位原因 -> 修改
        |
        v
跑边界场景
        |
        v
解释所有权、状态变化与资源释放
        |
        v
对照原项目
        |
        v
提交阶段版本
```

## 协作与验证约定

| 规则 | 具体做法 |
|---|---|
| 每次改动要小 | 一次只引入一个主要概念 |
| 编写核心逻辑 | 学习者编写，助手提供任务、接口提示、验收样例和代码评审 |
| 卡住时 | 先给提示，再解释具体代码 |
| 抽象按需出现 | 第一版用具体 `Worker` 和 `&mut self`；后面再引入 trait、`Arc`、原子变量 |
| 测试验证行为 | 测节点下线、超时、取消等场景，避免只测试 getter |
| 对照源码放在实现后 | 先形成自己的理解，再看原项目如何处理复杂情况 |
| 依赖逐步加 | 第一阶段只用标准库，HTTP 阶段再加入 Tokio 等依赖 |
| 阶段完成 | 功能验收通过，且能解释关键代码；保存可回看的版本 |

## 每课记录模板

按需在 `learning/lessons/` 新建笔记，例如 `stage-02-round-robin.md`。

| 内容 | 要回答的问题 |
|---|---|
| 本课任务 | 程序新增了什么行为？ |
| 新知识 | 本次引入了哪个 Rust 概念？ |
| 错误记录 | 编译器为什么拒绝之前的写法？ |
| 验收结果 | 哪些场景证明实现正确？实际执行了什么，结果如何？ |
| 源码差异 | 原项目为什么比迷你版复杂？ |

可直接使用以下模板：

```markdown
# 阶段 XX：课程名称

[返回学习入口](../index.md)

## 行为目标

## 新知识与关键解释

## 编译错误与修正原因

## 验收命令与结果

## 原仓库对照与差异

## 阶段版本
```

## 里程碑与节奏

| 里程碑 | 对应阶段 | 完成标志 |
|---|---|---|
| M1：同步轮询器 | 0～2 | 独立写出轮询器，能解释所有权和借用 |
| M2：可运行网关 | 3～6 | 启动两个假节点，用 `curl` 验证请求转发 |
| M3：并发与可靠性 | 7～9 | 节点变化、超时、重试和取消行为可验证 |
| M4：主线完成 | 10～12 | 支持流式响应、故障控制、观测和优雅停机 |

主线整体可先按每天约一小时、两到三个月估算，依据实际掌握程度调整。扩展专题另行安排，不计入这一估计。

详细内容见[主线实施计划](./02-mainline.md)，开始执行见[首批任务](./06-first-tasks.md)。
